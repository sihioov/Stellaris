Discord 승인 ≠ 즉시 커밋

작업은 끝났는데, 왜 다음 실행이 막혔을까?

Canopus는 AI가 만든 변경과 기존 변경이 섞이지 않도록 시작 전에 clean worktree를 요구합니다. 현재 병목은 README 생성이 아니라, approve 이후 finalize가 dry-run이라 커밋이 남지 않은 경계입니다.

흐름 보기상황 시뮬레이션
branch: main · status: dirty
!run요청이 task로 들어가고 Laniakea가 canopus submit 실행
AI stage completeREADME.md 생성, review까지 완료
!approvePendingReview → Processed, finalize 요청 기록
watch dry-runcommit/push/PR을 건너뛰어 README.md가 untracked로 남음
다음 submit: ?? README.md 때문에 worktree is not clean
Observed failure

오류는 “파일이 있다”가 아니라 “기준점이 없다”는 신호입니다.

$ git status --short ?? README.md $ canopus submit ... tool error: worktree is not clean state_root: /home/sihioov/project/MyNewProject/.canopus

진단

.canopus/는 이미 ignore됨
이번 dirty 원인은 런타임 디렉토리가 아닙니다.
README.md가 untracked
이전 AI 작업 산출물이 commit되지 않아 다음 작업의 안전 검사를 막습니다.
approve는 상태 전이
현재 구현에서는 commit이 아니라 finalizer에게 “진행 가능” 신호를 남깁니다.
Pipeline map

각 단계가 무엇을 보장하는지 클릭해서 확인하세요.

1. Pending

Discord !run이 task를 만들면 상태는 Pending입니다. 아직 repo에는 어떤 AI 변경도 적용되지 않았고, 실행 대기 상태입니다.

Decision boundary

approve, dry-run, mutate를 분리해야 운영 사고가 줄어듭니다.

Approve

  • 사람이 결과를 승인
  • task를 Processed로 전이
  • finalize 요청 메타데이터 기록
  • 현재 구현상 commit은 아님

Dry-run finalize

  • 변경 파일을 보고서로 남김
  • git add/커밋/push 생략
  • PR 생성 생략
  • 다음 submit이 dirty로 막힐 수 있음

Mutate finalize

  • git add -A 실행
  • agenda 기준 commit 생성
  • push/PR은 정책 gate 필요
  • local-commit-only 모드가 안전한 중간안

Scenario

다음 submit은 실패합니다

Dry-run finalize가 commit을 만들지 않아 ?? README.md가 남습니다. Canopus는 기존 변경과 새 AI 변경이 섞이는 것을 막기 위해 시작 전에 중단합니다.

지금 복구git add README.md 커밋 생성: Initialize project README
정책 개선approve → finalize finalize mode: local-commit-only
검증git status --short # empty output expected
Stop condition: repo가 clean이고, 승인된 변경이 commit 또는 명시적인 dry-run 산출물로 남아 있으며, 다음 Canopus submit이 prepare 단계에서 막히지 않는 상태.
